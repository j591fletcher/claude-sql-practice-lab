## Project Status

Actively developed. Core app is functional with a Node.js backend, static frontend, SQLite integration, and an Ollama-powered question generator with progress tracking.

## Project Goal

A personal SQL practice web app. SQLite databases are loaded from local files, and practice questions are generated by a local Ollama model based on the selected table and SQL topic. The user runs queries, checks their answer against an expected result set, and can request hints.

## Getting Started

- Install dependencies: `npm install`
- Add `.db`, `.sqlite`, or `.sqlite3` files to `data/` — or load CSV data with `node scripts/load-csv.js`
- Copy `.env.example` to `.env` and configure as needed
- Start the app: `npm start` (runs on `http://localhost:4000`)

## Architecture

- `server.js` — Express backend, all API routes, SQLite and Ollama integration
- `public/` — Static frontend (HTML/CSS/JS, no framework)
- `data/` — SQLite database files and source CSVs
- `state/` — Auto-created at runtime; holds `progress.db` (SQLite) for session state
- `scripts/load-csv.js` — Loads CSV files from `data/` into a SQLite database
- `tests/api.test.js` — API smoke tests

## Key API Routes

| Method | Route | Purpose |
|--------|-------|---------|
| GET | `/api/databases` | List available `.db` files in `data/` |
| GET | `/api/tables?db=` | List tables in a database |
| GET | `/api/schema?db=&table=` | Column info for a table |
| POST | `/api/generate-problem` | Generate a practice problem via Ollama |
| POST | `/api/check-answer` | Compare user query result to expected result set |
| POST | `/api/validate-sql` | Run a query and return rows (no answer check) |
| POST | `/api/generate-hint` | Get a hint for the current problem |
| GET | `/api/solution/:problemId` | Reveal the correct SQL |
| GET/POST | `/api/progress` | Read or update per-topic practice counts |

## Question Generator Design

Problems are generated by a local Ollama model (`OLLAMA_MODEL`, default `gemma3:27b`) at `OLLAMA_BASE_URL` (default `http://localhost:11500`).

The prompt is built from several layers:
- **Schema block** — column names with types, PK/NOT NULL markers, and foreign key relationships
- **Sample rows** — 3 rows from each selected table
- **`TOPIC_CONTEXT`** — per-topic description of what a good question must demonstrate
- **Rules** — positive constraints on the problem statement and SQL
- **Variety block** — last 7 generated problems for this topic (from `recent_problems` table) passed as an avoid list, plus a random angle from `TOPIC_ANGLES`

Generated problems are stored in memory (`pendingProblems` map) keyed by UUID. The expected SQL is executed immediately on generation and the result set is stored for answer checking. Problem history persists across restarts in `state/progress.db`.

## Environment Variables

| Variable | Default | Purpose |
|----------|---------|---------|
| `PORT` | `4000` | HTTP port |
| `DATA_DIR` | `./data` | Directory scanned for `.db` files |
| `STATE_DIR` | `./state` | Directory for `progress.db` |
| `OLLAMA_MODEL` | `gemma3:27b` | Ollama model to use |
| `OLLAMA_BASE_URL` | `http://localhost:11500` | Ollama API host |

## Notes

- This app is intended for local personal use — no auth, no shared state, no cloud hosting needed
- `pendingProblems` is in-memory only and resets on server restart; `progress.db` persists topic counts and recent problem history
- Multi-table topics (JOINs, UNION, etc.) automatically select two tables; single-table topics select one
